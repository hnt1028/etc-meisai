# テスト方針

テストの種類と内容を定める。テストを書く義務は CLAUDE.md の基本ルールに従う。

## 単体テスト（`test/`）

- 対象: CSVパーサー、重複判定、上書き規則、料金の計算などのロジック
- CSVパーサーは必ず書く。次のケースを含める
  - 正常系
  - 割引前料金・ＥＴＣ割引額の空欄（`null` になること）
  - 通行料金・還元額適用料金・後納料金の空欄（エラーになること）
  - 文字コード（CP932）
  - 列数が足りない行（何が不正かを示すエラーになること）
  - 同じCSVを2回取り込んでも件数が増えないこと
  - 全角・半角のヘッダー照合
  - 備考の「確定」「確認中」と割引種別の判定
  - 上書き規則の4パターン（[csv-format.md](csv-format.md) の表）

## ウィジェットテスト（`test/`）

- 対象: 3画面の主要な表示パターン
- 例: 明細が0件のとき、確認中の行があるとき、カード番号が下4桁だけで表示されること

- 画面の大きさ（[specification.md](specification.md) の 3.8）: `test/userinterface/layout_test.dart` が、主な画面を、小さいスマートフォン（320×568）、スマートフォン（360×640、文字1.5倍を含む）、横向き（800×360）、タブレット（縦・横）で順に開く。レイアウトのはみ出しは、テストでは例外になるので、そこで失敗する。新しい画面を足したときは、このテストの手順にも足す

## 結合テスト（`integration_test/`）

- 対象: CSV選択から取込、一覧表示、ルート表示までの一連の流れ
- 入力は架空のCSVをテスト用フィクスチャとして `test/fixtures/` に置く
- 実データのCSVは使わない（[privacy.md](privacy.md) に従う）

## 共通

- テストデータは架空のものだけを使う
- 不具合を直したときは、その不具合を再現するテストを先に書く
