# 設計書

実装時に、設計書を **画面・処理・テーブル** ごとに1ファイルずつ作成する。仕様（何を作るか）は [specification.md](specification.md) に書き、設計書には実装の方法だけを書く。

## 配置

```
docs/systems/
  screens/     # 画面（SCR-）
  processes/   # 処理（PRC-）
  tables/      # テーブル（TBL-）
  ledgers/     # 台帳（種別ごとに1つ。IDの管理に使う）
```

## 台帳

- 種別ごとに `ledgers/` 配下に台帳を1つ置く（`screens.md`、`processes.md`、`tables.md`）
- 設計書を作成・改名・廃止するときは、台帳も同じ変更で更新する
- 台帳の列: ID、名称、ファイル、状態（草案 / 確定 / 廃止）
- 新しいIDは、台帳の最大の連番に1を足して採番する
- 廃止したIDは台帳に残し、状態を「廃止」にする（削除しない。IDの再利用を防ぐため）

## ID

- 形式: `種別ID-連番-英語の短い名前.md`（例: `SCR-001-statement-list.md`）
- 種別ID: `SCR`（画面）、`PRC`（処理）、`TBL`（テーブル）
- 連番は3桁。一度付けたIDは変えず、削除したIDは再利用しない
- 他の設計書から参照するときは、ファイル名ではなくIDで書く（例: 「PRC-001 の結果を SCR-001 に表示する」）

## シーケンス図

処理の設計書のシーケンス図は、Mermaid の `sequenceDiagram` で書く。

| 表すもの | 書き方 |
|---|---|
| 同期の呼び出し（`Future` を返さない呼び出し） | `->>` |
| 同期の戻り | `-->>` |
| 非同期の呼び出し（`Future` を返す呼び出し） | `-)` |
| 非同期の戻り | `--)` |
| 実行仕様（呼び出された側が処理している間） | `activate` と `deactivate` で描く |

- 呼び出しごとに、対応する戻りを必ず描く
- 実行仕様は、呼び出しを受けてから戻りを返すまでの区間に描く

## 各ファイルに書く内容

- ID と名称
- 概要（1〜3行）
- 本文（種別ごとに必要な項目を書く。下の各節）
- 関連するテストの種類（[testing.md](testing.md) の単体・ウィジェット・結合）

### 画面

基本設計と詳細設計に分けて書く。

**基本設計**

- 画面イメージ: 画面の構成が分かる図。テキストの枠図（コードブロック）で書くか、画像ファイルを `docs/systems/screens/images/` に置いて参照する
- 入出力項目一覧: 画面の項目ごとに、項目名、入力か出力か、型、表示形式（例: ETCカード番号は下4桁）を表にする
- 操作一覧: 操作ごとに、操作名、きっかけ（タップなど）、動作、遷移先（他画面のIDで書く）を表にする
- エラー一覧: エラーごとに、発生する場面、表示する文言（文字列定数の名前）、操作の続け方を表にする

**詳細設計**

- シーケンス図: 画面から呼ばれる処理ごとに、操作と処理のIDの対応を表にする。図そのものは処理の設計書（PRC）の「シーケンス図」に書き、画面の設計書には書き写さない

### 処理

- 入力、手順、出力、エラー時の動作
- 実装箇所（ファイルとクラス）
- 呼び出し箇所
- シーケンス図（上の「シーケンス図」の書き方に従う）

### テーブル

- 実装箇所（drift のテーブル定義のファイルとクラス）
- 使う箇所（読み書きする Repository）
- 項目一覧: 項目ごとに、論理カラム名、物理カラム名、データ型、桁数、NotNull を表にする
- キー（主キー・重複判定のキー）と制約
- インデックス: 名前、対象のカラム、種類（ユニークかどうか）を表にする
