# 設計書

実装時に、設計書を **画面・処理・テーブル・API** ごとに1ファイルずつ作成する。仕様（何を作るか）は [specification.md](specification.md) に書き、設計書には実装の方法だけを書く。

## 配置

```
docs/systems/
  screens/     # 画面（SCR-）
  processes/   # 処理（PRC-）
  tables/      # テーブル（TBL-）
  apis/        # API（API-）。アプリ内のインターフェースも含む（例: リポジトリ、地図タイル取得）
  ledgers/     # 台帳（種別ごとに1つ。IDの管理に使う）
```

## 台帳

- 種別ごとに `ledgers/` 配下に台帳を1つ置く（`screens.md`、`processes.md`、`tables.md`、`apis.md`）
- 設計書を作成・改名・廃止するときは、台帳も同じ変更で更新する
- 台帳の列: ID、名称、ファイル、状態（草案 / 確定 / 廃止）
- 新しいIDは、台帳の最大の連番に1を足して採番する
- 廃止したIDは台帳に残し、状態を「廃止」にする（削除しない。IDの再利用を防ぐため）

## ID

- 形式: `種別ID-連番-英語の短い名前.md`（例: `SCR-001-statement-list.md`）
- 種別ID: `SCR`（画面）、`PRC`（処理）、`TBL`（テーブル）、`API`（API）
- 連番は3桁。一度付けたIDは変えず、削除したIDは再利用しない
- 他の設計書から参照するときは、ファイル名ではなくIDで書く（例: 「PRC-001 の結果を SCR-001 に表示する」）

## 各ファイルに書く内容

- ID と名称
- 概要（1〜3行）
- 本文（種別ごとに必要な項目を書く）
  - 画面: 表示項目、操作、遷移先（他画面のIDで書く）
  - 処理: 入力、手順、出力、エラー時の動作
  - テーブル: 列名、型、制約、キー
  - API: 引数、戻り値、エラー
- 関連するテストの種類（[testing.md](testing.md) の単体・ウィジェット・結合）
