# ルートマップとICマスタ

- CSVに座標も路線名もないため、IC名から座標と路線名を引く「ICマスタ」をアプリ同梱アセットとして持つ
- マスタに無い、または一つに決まらないIC名の区間は「位置不明」とし、一覧には表示、地図では除外して通知する（落とさない）
- 経路は、入口から出口まで、間のICを通る折れ線で描く（下の「地図に描く経路」）。道路そのものの形ではなく、ICの位置をつないだ折れ線である
- 地図の表示と操作は [SCR-005](systems/screens/SCR-005-route-map.md) に従う
- 地図は `flutter_map` + OpenStreetMap を使う（外部通信の制限は [privacy.md](privacy.md) に従う）

## ICマスタの出どころ

国土交通省「国土数値情報（高速道路時系列データ）N06」の2025年版（現況データとして使う）。

- 入手元: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N06-2025.html
- 利用条件: CC BY 4.0 と互換の利用規約。出典と、加工した旨を表示する（下の「出典の表示」）
- 使う地物: 接合部（IC・JCT・スマートIC・PA などの点）と、路線区間（線）。設置期間の終了が 9999（現在も存在する）ものだけを使う

N06 に無い料金所・出入口（東京湾アクアラインなど）は、OpenStreetMap（© OpenStreetMap contributors、ODbL）から補う。

- 使う地物: 名前のある料金所（`barrier=toll_booth`）と、出入口（`highway=motorway_junction`）。PA・SA は使わない
- 補うのは、名前が N06 のどの地点とも一致しない（末尾を取り除いても一致しない）ものだけ。同じ名前（末尾を取り除いたもの）の点が複数あるときは、1地点にまとめる（位置は平均。1.5km以上離れた点は除く）
- 路線名は、N06 の路線区間が50m以内にあればそれを使う。無いときは、下の「路線の補足」で決める。どちらも無いときは、路線名なし
- 加工した地点は、`kind` が 4（その他）、`id` が `osm:` で始まる
- 補った地点は ODbL の対象。出典（© OpenStreetMap contributors）は、設定画面と地図に表示する

## マスタの作り方

`tool/build_ic_master.dart` が、N06 の GeoJSON（`N06-25_Joint.geojson`、`N06-25_HighwaySection.geojson`）と、OpenStreetMap の料金所・出入口のJSONから、`assets/ic_master.json` を作る。ネットワークには接続しない。

```bash
dart run tool/build_ic_master.dart <N06のGeoJSONがあるフォルダ> <OSMのJSON> assets/ic_master.json
```

OSM の JSON は、Overpass API の次の問い合わせの結果（`out tags center`）。

```
[out:json][timeout:240];
area["ISO3166-1"="JP"]->.jp;
(
node["barrier"="toll_booth"]["name"](area.jp);
node["highway"="motorway_junction"]["name"](area.jp);
);
out tags center;
```

- 接合部1件が、マスタの1地点になる。`id`（N06の関係ID）、`name`（地点名）、`kind`（接合部種別）、`lat`・`lon`（緯度経度）、`routes`（路線名のリスト）を持つ
- `routes` は、地点から50m以内にある路線区間の路線名（重複なし）。N06では、現在の接合部はすべて路線区間の上にある。JCTやIC は、2〜3路線になることがある
- `links` は、道路に沿って隣り合う地点の組と、その間の道のり（メートル）。`[地点のid, 地点のid, 道のり]` の並び。地点の間の距離を求めるために使う（下の「地点の間の距離」）
- `kind` は、1: 一般IC（都市高速のランプを含む）、2: スマートIC、3: JCT、4: その他（PAなど）
- ツールの処理は `tool/ic_master_builder.dart`。`test/tool/ic_master_builder_test.dart` で確かめる。作ったマスタの整合（IDが重複しない、すべての地点に路線名がある、座標が日本の範囲）は、`test/infrastructure/repository/ic_mapping/ic_repo_test.dart` が確かめる
- N06 を新しい版に差し替えるときは、このコマンドを実行し直す。`id` は版をまたいで同じ地点を指す（関係ID）

### リンクの作り方

N06 の路線区間（線）を、道路の網（点と、点をつなぐ辺）として扱い、地点を網に結びつけて、隣り合う地点を見つける。

1. 路線区間の線を、100m以下の間隔の点に分け、点をつなぐ辺にする。点の座標は、約20mの格子にそろえる（ジャンクションで、別の路線の端がつながるように）
2. 各地点（N06 と OpenStreetMap から補ったもの）を、最も近い点に結びつける。150m以内に点が無い地点は、網に載らない（東京湾アクアラインなど、N06 に区間が無い道路）
3. すべての地点を同時に始点として、道のりが最も短い始点を、各点に割り当てる（最短経路の探索を、全地点から同時に行う）。割り当てが違う2点をつなぐ辺があれば、その2つの地点を隣り合うとして、道のり（始点から2点までの道のりと辺の長さの和）を、リンクにする。同じ組は、短いほうを残す
4. 道のりは、メートルに丸める

- 隣り合う地点は、PAなどの種別4の地点も含む。道のりを足していくので、途中に何があっても、合計は変わらない
- 検算: 作ったマスタで、既知の2地点の道のりが、公表されている距離とおよそ合うことを確かめる（`test/tool/ic_master_builder_test.dart` は、小さな網で確かめる）

## 地点の間の距離

2つの地点（IC地点）の間の距離は、`links` を辺とする網の最短経路の長さ（リンクの道のりの和）とする（実装は `IcDistance`）。

- 利用者が乗り換えたジャンクションの先も、経路に入る（最短のものを選ぶ）
- 経路が無いとき（どちらかが網に載らない、または、つながっていない）は、2つの地点の位置の直線距離（球面の近似）にする
- 道路に沿った距離であって、料金所・ランプの出入りは含まない。実際の走行距離とは違う（推定）

## 地図に描く経路

明細行の線は、入口から出口まで、**間にあるICの位置を順につないだ折れ線**で描く。入口と出口の2点の直線ではなく、実際の路線図に近づける。

- 間のICは、「地点の間の距離」で求める最短経路が通る地点（PAなども含む）。入口の位置、間の地点の位置、出口の位置の順に、つなぐ
- 入口・出口のどちらかの位置を、利用者が地図で指定したとき（地点でなく、指定した位置を使うとき）は、間の地点を求めず、2点の直線にする
- 経路が無いとき（どちらかが道路の網に載らない、または、つながっていない。東京湾アクアラインなど）も、2点の直線にする
- 距離（集計）と、線の形は、同じ最短経路から作る（実装は `IcDistance` の `roadRouteBetween`）

## IC名の照合

CSVのIC名と、マスタの `name` を、次の順で照合する（実装は `IcLookup`。[PRC-005](systems/processes/PRC-005-list-ic-matches.md)）。

1. 利用者が登録した対応づけ（[SCR-004](systems/screens/SCR-004-ic-mapping.md)）があれば、それを使う
2. 全角の英数字・記号を半角にし、大文字・小文字を区別せず、空白を取り除いた（以下「そろえた」）IC名が、そろえたマスタの `name` と等しい地点を探す。1件なら一致
3. 無ければ、そろえたIC名とマスタの `name` の末尾の「スマートIC」「スマート」「SIC」「JCT」「IC」「出入口」「入口」「出口」「本線料金所」「料金所」「本線」（どれか1つ）を取り除いて比べる。1件なら一致
4. 無ければ、IC名の末尾の「第一」「第二」「第三」「上」「下」「内」「外」「東」「西」「南」「北」（どれか1つ。取り除いた名前が2文字以上のとき）を取り除き、2・3と同じ照合をする。1件なら一致（**近似**。料金所やランプが、同名のIC地点に結びつく）。首都高速などでは、「永福上」「みなとみらい下」「霞が関内」のように、IC名に上り・下り・内回り・外回りが付き、「木更津金田第一」のように、料金所の番号が付く
5. 2件以上あれば「複数候補」、0件なら「未一致」。どちらも利用者が決める（SCR-004）

- NEXCO のIC名は「IC」が付くことが多く、首都高速などでは「出入口」「入口」「出口」が使われる。末尾の除去は、この違いをそろえるためのもの
- 取り除くと名前が空になるときは、取り除かない
- 「…本線」（本線料金所。例: 中央自動車道と首都高速の境にある料金所）は、末尾の「本線」を取り除いて、同名のIC地点に結びつける。この位置は料金所の位置ではなく、**IC地点の位置を使った近似**である。料金所の位置を持つ公開データは、国土数値情報には無い。OpenStreetMap には、名前のある料金所が一部にあり、N06 に無い名前は、それを補う（上の「ICマスタの出どころ」）。補っても、この「本線」のように同名のIC地点にしか結びつかないものは、近似のまま
- 料金所の正確な位置は、ルートマップの画面で、利用者が地図を指して登録できるようにする（次の段階。登録した位置は端末内に保存し、近似より優先する）
- マスタに地点が無い名前は、未一致になる

## 位置の優先順

IC名の位置は、次の順で決める（実装は `IcLookup` の `placeOf`）。

1. 利用者が地図で指定した位置（[TBL-003](systems/tables/TBL-003-ic-positions.md)）
2. 対応づけで選んだ地点の位置（[SCR-004](systems/screens/SCR-004-ic-mapping.md)）、または自動で一致した地点の位置
3. どれも無ければ「位置不明」（地図に描かず、通知する）

- 利用者の指定は、IC名ごとに1つ（CSVの表記のまま）。解除すると、2 に戻る
- 地点の位置のうち、末尾の「本線」を除いて一致したもの（料金所）と、手順4（末尾の上下など）で一致したものは、近似として、地図のマーカーに「近似」と表示する。指定した位置には表示しない

## 路線名（通行した高速道路）

明細行の路線名は、入口ICと出口ICの地点（上の照合で決まったもの）から決める（[PRC-004](systems/processes/PRC-004-list-statement-lines.md)）。

- 入口と出口の両方の地点が分かり、両方に共通の路線名があるときは、共通の路線名
- 共通が無いとき（JCTで乗り換えたときなど）は、両方の路線名を、重複なしでつないだもの
- 片方の地点だけが分かるときは、その地点の路線名。入口が空欄のときは、出口の地点の路線名
- どちらも分からないときは、路線名なし（画面には「-」）
- 地点が分からなくても、IC名が「路線の補足」（下記）に当たるときは、その路線名を、地点の路線名の代わりに使う。上の規則は、これを含めて同じように働く
- 路線名はICが載っている路線であり、実際に走った道は保証しない（直線の距離でなく、ICの所属で決めるため）

### 路線の補足

N06 には載っていない路線（東京湾アクアラインなど）があり、そのIC名は地点に決まらない。入口が空欄になりやすい路線でもあり、そのままでは路線名が空になる。そこで、IC名の先頭の文字から路線名を決める、小さな対応表をコードに持つ（`lib/application/usecase/ic_mapping/ic_route_supplements.dart`）。

| IC名の先頭（全角・半角、空白を区別しない） | 路線名 |
|---|---|
| 木更津金田 | 東京湾アクアライン |
| アクア | 東京湾アクアライン |
| 海ほたる | 東京湾アクアライン |

- 補足は路線名だけを決める。位置は、OpenStreetMap から補った地点があればそれを使い、無ければ [SCR-005](systems/screens/SCR-005-route-map.md) で利用者が指定する
- 地点が決まり、その地点に路線名があるときは、地点の路線名を使う（補足は使わない）。地点に路線名が無いとき（OpenStreetMap から補った地点で、N06 の路線区間が近くに無いもの）は、補足を使う
- 路線を足すときは、この表とコードの対応表を同時に直す
