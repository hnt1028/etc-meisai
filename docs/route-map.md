# ルートマップとICマスタ

- CSVに座標も路線名もないため、IC名から座標と路線名を引く「ICマスタ」をアプリ同梱アセットとして持つ
- マスタに無い、または一つに決まらないIC名の区間は「位置不明」とし、一覧には表示、地図では除外して通知する（落とさない）
- 経路はまずIC間の直線で描画する。道路に沿った経路は後続の段階で検討する
- 地図の表示と操作は [SCR-005](systems/screens/SCR-005-route-map.md) に従う
- 地図は `flutter_map` + OpenStreetMap を使う（外部通信の制限は [privacy.md](privacy.md) に従う）

## ICマスタの出どころ

国土交通省「国土数値情報（高速道路時系列データ）N06」の2025年版（現況データとして使う）。

- 入手元: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N06-2025.html
- 利用条件: CC BY 4.0 と互換の利用規約。出典と、加工した旨を表示する（下の「出典の表示」）
- 使う地物: 接合部（IC・JCT・スマートIC・PA などの点）と、路線区間（線）。設置期間の終了が 9999（現在も存在する）ものだけを使う

## マスタの作り方

`tool/build_ic_master.dart` が、N06 の GeoJSON（`N06-25_Joint.geojson`、`N06-25_HighwaySection.geojson`）から `assets/ic_master.json` を作る。ネットワークには接続しない。

```bash
dart run tool/build_ic_master.dart <N06のGeoJSONがあるフォルダ> assets/ic_master.json
```

- 接合部1件が、マスタの1地点になる。`id`（N06の関係ID）、`name`（地点名）、`kind`（接合部種別）、`lat`・`lon`（緯度経度）、`routes`（路線名のリスト）を持つ
- `routes` は、地点から50m以内にある路線区間の路線名（重複なし）。N06では、現在の接合部はすべて路線区間の上にある。JCTやIC は、2〜3路線になることがある
- `kind` は、1: 一般IC（都市高速のランプを含む）、2: スマートIC、3: JCT、4: その他（PAなど）
- ツールの処理は `tool/ic_master_builder.dart`。`test/tool/ic_master_builder_test.dart` で確かめる。作ったマスタの整合（IDが重複しない、すべての地点に路線名がある、座標が日本の範囲）は、`test/infrastructure/repository/ic_mapping/ic_repo_test.dart` が確かめる
- N06 を新しい版に差し替えるときは、このコマンドを実行し直す。`id` は版をまたいで同じ地点を指す（関係ID）

## IC名の照合

CSVのIC名と、マスタの `name` を、次の順で照合する（実装は `IcLookup`。[PRC-005](systems/processes/PRC-005-list-ic-matches.md)）。

1. 利用者が登録した対応づけ（[SCR-004](systems/screens/SCR-004-ic-mapping.md)）があれば、それを使う
2. 全角の英数字・記号を半角にし、大文字・小文字を区別せず、空白を取り除いた（以下「そろえた」）IC名が、そろえたマスタの `name` と等しい地点を探す。1件なら一致
3. 無ければ、そろえたIC名とマスタの `name` の末尾の「スマートIC」「スマート」「SIC」「JCT」「IC」「出入口」「入口」「出口」「本線」（どれか1つ）を取り除いて比べる。1件なら一致
4. 2件以上あれば「複数候補」、0件なら「未一致」。どちらも利用者が決める（SCR-004）

- NEXCO のIC名は「IC」が付くことが多く、首都高速などでは「出入口」「入口」「出口」が使われる。末尾の除去は、この違いをそろえるためのもの
- 取り除くと名前が空になるときは、取り除かない
- 「…本線」（本線料金所。例: 中央自動車道と首都高速の境にある料金所）は、末尾の「本線」を取り除いて、同名のIC地点に結びつける。この位置は料金所の位置ではなく、**IC地点の位置を使った近似**である。料金所の位置を持つ公開データは見つからなかった（国土数値情報には無い。OpenStreetMap には、名前のある本線料金所がほとんど無く、確認した例では名前の点が無かった）
- 料金所の正確な位置は、ルートマップの画面で、利用者が地図を指して登録できるようにする（次の段階。登録した位置は端末内に保存し、近似より優先する）
- マスタに地点が無い名前は、未一致になる

## 位置の優先順

IC名の位置は、次の順で決める（実装は `IcLookup` の `placeOf`）。

1. 利用者が地図で指定した位置（[TBL-003](systems/tables/TBL-003-ic-positions.md)）
2. 対応づけで選んだ地点の位置（[SCR-004](systems/screens/SCR-004-ic-mapping.md)）、または自動で一致した地点の位置
3. どれも無ければ「位置不明」（地図に描かず、通知する）

- 利用者の指定は、IC名ごとに1つ（CSVの表記のまま）。解除すると、2 に戻る
- 地点の位置のうち、末尾の「本線」を除いて一致したもの（料金所）は、近似として、地図のマーカーに「近似」と表示する。指定した位置には表示しない

## 路線名（通行した高速道路）

明細行の路線名は、入口ICと出口ICの地点（上の照合で決まったもの）から決める（[PRC-004](systems/processes/PRC-004-list-statement-lines.md)）。

- 入口と出口の両方の地点が分かり、両方に共通の路線名があるときは、共通の路線名
- 共通が無いとき（JCTで乗り換えたときなど）は、両方の路線名を、重複なしでつないだもの
- 片方の地点だけが分かるときは、その地点の路線名。入口が空欄のときは、出口の地点の路線名
- どちらも分からないときは、路線名なし（画面には「-」）
- 地点が分からなくても、IC名が「路線の補足」（下記）に当たるときは、その路線名を、地点の路線名の代わりに使う。上の規則は、これを含めて同じように働く
- 路線名はICが載っている路線であり、実際に走った道は保証しない（直線の距離でなく、ICの所属で決めるため）

### 路線の補足

N06 には載っていない路線（東京湾アクアラインなど）があり、そのIC名は地点に決まらない。入口が空欄になりやすい路線でもあり、そのままでは路線名が空になる。そこで、IC名の先頭の文字から路線名を決める、小さな対応表をコードに持つ（`lib/application/usecase/ic_mapping/ic_route_supplements.dart`）。

| IC名の先頭（全角・半角、空白を区別しない） | 路線名 |
|---|---|
| 木更津金田 | 東京湾アクアライン |
| アクア | 東京湾アクアライン |
| 海ほたる | 東京湾アクアライン |

- 補足は路線名だけを決める。位置は決めない（地図に描くには、[SCR-005](systems/screens/SCR-005-route-map.md) で位置を指定する）
- 対応づけ（[SCR-004](systems/screens/SCR-004-ic-mapping.md)）や自動の一致で地点が決まるときは、地点の路線名を使う（補足は使わない）
- 路線を足すときは、この表とコードの対応表を同時に直す

## 出典の表示

アプリの設定画面（[SCR-001](systems/screens/SCR-001-settings.md)）に、次の文を表示する。

> 出典：国土交通省 国土数値情報（高速道路時系列データ）（https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N06-2025.html）を加工して作成

- 加工の内容: 接合部と路線区間から、IC名・座標・路線名の対応表を作成した
