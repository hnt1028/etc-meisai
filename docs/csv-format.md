# 利用明細CSV

利用者が「ETC利用照会サービス」から出力した「利用明細CSV」をインポートする。各項目の意味は、同サービスの[表示内容の説明](https://www.etc-meisai.jp/soukou_meisai_exp.html)に従う（以下の「表示内容の説明との対応」）。

## 列（この順序）

1. 利用年月日（自） 2. 時分（自） 3. 利用年月日（至） 4. 時分（至）
5. 利用ＩＣ（自） 6. 利用ＩＣ（至）
7. 割引前料金 8. ＥＴＣ割引額 9. 通行料金 10. 還元額適用料金 11. 後納料金
12. 車種 13. 車両番号 14. ＥＴＣカード番号 15. 備考

## パース方針

- 文字コードは CP932（Shift_JIS の Windows 拡張）。ヘッダーは1行目、データは2行目以降
- ヘッダーは仕様の列名と完全一致することを確認する（列名は全角表記。例: `利用ＩＣ（自）`、`ＥＴＣカード番号`）
- 日付は `yy/mm/dd`（西暦下2桁）、時刻は `HH:mm`
- 「割引前料金」「ＥＴＣ割引額」の空欄は `null`（0と区別する）。表示内容の説明では、当面の間、NEXCO の道路だけが表示される。NEXCO 以外の道路の行は、空欄になる
- 「還元額適用料金」の空欄は `0` として取り込む。確認中の行（割引の調整が反映される前）で、空欄になることがある（実際のファイルで確認した。このとき「後納料金」は「通行料金」と同額）。`null` にはしない
- 他の金額（通行料金・後納料金）の空欄は、不正としてエラーにする（`null` にしない）
- 入口（利用年月日（自）・利用ＩＣ（自））が空欄の行がある。`entranceAt` と `entranceIc` は `null` を許可する
- 「備考」は `;` 区切りの文字列。含まれるのは「状態」（`確定` か `確認中`）と、0個以上の「割引種別」（`深夜割引`、`休日割引`、`ＥＴＣ通常`、`乗継調整`、`ＥＴＣ通常＊１` など。障害者割引が重なると `＊１` が付く）。割引種別は状態ではないので、状態と分けて扱う
- 備考のうち、次のものは割引種別にしない（割引や料金の調整ではないため）: 実際の利用年月日（`yy/mm/dd`。調整などで、利用年月日が実際と異なるときに付く）、`更新あり`、`削除あり`（利用証明書の発行後に、明細に変更・削除があったときに付く）。これらは、読み飛ばす（保存しない）
- 「ＥＴＣカード番号」は出力時点で一部が `*` でマスクされている。それでも個人情報として扱う
- 想定外の形式は、何が不正かが分かるエラーで失敗させる（黙って捨てない）
- パーサーはUIから独立させ、単体テスト可能にする

## 実データで確認済みの事項（2026-11-14 出力のCSV、126行）

- 列数は15で、ヘッダーは仕様と一致
- 「通行料金」＝「割引前料金」＋「ＥＴＣ割引額」（割引額は負の値）
- 「通行料金」＝「還元額適用料金」＋「後納料金」（全行で成り立つ）
- 「還元額適用料金」は、`0` か空欄（空欄は `0` として読む）、「後納料金」は全行「通行料金」と同額。このファイルではマイレージの還元を使っていない、と読める
- 「還元額」（ポイント交換で得た額）に相当する列は無い
- 「後納料金」は、ETCカードに後日請求される部分。「還元額適用料金」は、還元額で充当された部分（ETC利用照会サービスの表示内容の説明に基づく）
- 「備考」の「確認中」は、通行止めによる料金調整、社会実験割引、一部の時間帯割引などが適用される前の金額（表示内容の説明）。確定後に照合する必要がある

## 空欄の項目（車両番号、入口日時、入口IC）

一般レーンから進入し、料金所でETCカードで支払った利用などで、「車両番号」と「利用年月日（自）」「時分（自）」が空欄になる行がある。「利用ＩＣ（自）」が空欄になる行もある（表示内容の説明では、通行料金が均一の路線を利用した場合などは、入口ICが表示されない）。

- 空欄の「車両番号」は、エラーにしない。車両番号なし（`null`）として取り込む。空欄以外で、数字でないときは、これまでどおりエラーにする
- 空欄の入口（利用年月日（自）・時分（自）・利用ＩＣ（自））は、これまでどおり、入口なし（`null`）として取り込む
- 利用者は、空欄の項目だけ、後から入力できる。入力は、項目ごとに1回だけで、入力すると変えられない。CSVに値がある項目は、変えられない
  - 車両番号: [PRC-014](systems/processes/PRC-014-save-vehicle-number.md)
  - 入口日時（日付と時分）、入口IC: [PRC-015](systems/processes/PRC-015-save-entrance.md)
- 入力した値は、CSVの値とは別に保存する。**重複判定のキーは、CSVの値だけで作る**（入口日時・入口ICを入力しても、キーは変わらない）。そのため、同じCSVを取り込み直しても、別の行として増えない

## 表示内容の説明との対応

[表示内容の説明](https://www.etc-meisai.jp/soukou_meisai_exp.html)（ETC利用照会サービス）と、このアプリの扱いの対応。

| 項目 | 表示内容の説明 | このアプリ |
|---|---|---|
| 利用ＩＣ（自） | 入口。通行料金が均一の路線などでは、表示されない場合がある | 空欄は入口なし（`null`）。利用者が入力できる |
| 割引前料金・ＥＴＣ割引額 | 当面の間、NEXCO のみ表示 | NEXCO 以外では空欄（`null`） |
| 通行料金 | 割引前料金からＥＴＣ割引額を引いた額。確認中は、調整や一部の割引の前の額 | そのまま `fare`。確認中は、後の取込で置き換える |
| 還元額適用料金 | 通行料金のうち、ＥＴＣマイレージサービスの還元額で支払った額 | `fareAfterRebate`。空欄は 0 |
| 後納料金 | 通行料金のうち、ＥＴＣカードで後払いする額 | `postpaidFare` |
| 車種 | 車種番号 1〜5。事業者ごとに区分表が違う | 番号 1〜5 を、NEXCO の区分1の名前で表示する（`VehicleTypeValue`） |
| 備考 | 状態、割引・調整名、実際の利用年月日、更新あり・削除あり | 状態と、割引・調整名（割引種別）だけ使う。日付・更新あり・削除ありは、読み飛ばす |

## 重複判定（再取込しても増えない）

「利用年月日(自)・時分(自)・利用IC(自)・利用IC(至)・ETCカード番号」の組み合わせをキーとする。

## 取込時の上書き規則（確定・確認中）

同じキーの明細行が既に保存されているときは、保存済みの状態で次のように扱う。

| 保存済みの状態 | 取り込む行の状態 | 扱い |
|---|---|---|
| 確定 | 確定 / 確認中 | 無視する（保存済みの値を残す） |
| 確認中 | 確定 | 上書きする（確定後の値に置き換える） |
| 確認中 | 確認中 | 上書きする（最新の値に置き換える） |
| なし | どちらでも | 新規に保存する |

- 「確定」は、保存済みの値を変えない最終状態として扱う
- 状態は「備考」の中の `確定` / `確認中` で判定する。割引種別は判定に使わない
- 「確認中」は割引や通行止めの調整が反映される前の金額なので、後の取込で置き換えてよい
- 上書きするとき、利用者が入力した入口日時・入口ICは、そのまま残る（CSVの値とは別に保存してあるため）。入口日時・入口ICは、CSVに値があれば、CSVの値を使う（利用者の入力より優先する）
- 上書きするとき、取り込む行の車両番号が空欄で、保存済みの行に車両番号があるとき（利用者が入力したもの）は、保存済みの車両番号を残す。取り込む行に車両番号があるときは、取り込む行の値にする

### 注意

- 確認中の行は、確定時に「利用年月日（至）」「時分（至）」が変わる可能性がある。その場合はキーが変わり、同じ明細行が2件になる。取込のテストでこのケースを確認する
